# Assets

Assets bring together the elements useful for managing data (such as data storage media, premises, tangible or intangible items). &#x20;

This referential lets you list assets, whether internal or external to the organization (applications, resources, buildings...).&#x20;

Here you should list the applications, software, or other items that serve as **data storage media**.

_For example, if you use a CRM-type customer relationship software, add it to this list._

**The goal is to let you keep track of your data storage media and link your assets to your data catalog.**

Note: Assets are not necessarily linked to data processors. For example, it could be a **piece of software installed on the server without the publisher being involved in processing personal data**.

### Adding a new asset:&#x20;

To add a new asset, you can:&#x20;

* start from existing templates
* use AI
* create an asset directly in the referential
* import an asset from a csv/excel or JSON file
* create an asset from a questionnaire: this requires having an asset-creation questionnaire template

### Attaching an asset to an organizational unit

By default, an asset created in Dastra is accessible to the entire organization (global scope). It's possible to **attach an asset to a specific organizational unit** in order to limit its visibility to the users of that entity or department.

To do this, when creating or editing the asset, select the desired organizational unit in the dedicated field. The asset will then only be visible to users who have access to that organizational unit.
